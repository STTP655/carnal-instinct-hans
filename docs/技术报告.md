# 技术报告：Carnal Instinct（UE 5.5 Shipping）UI 汉化的可行与不可行

> 本报告的全部结论都来自实测（日志、字节级对比、游戏内验证），并标注了证伪过程。
> 目的：让后来者不必重复我们踩过的坑。

---

## 一、最终方案：UE4SS Lua pre-hook `TextBlock:SetText`

```lua
local UH = require("UEHelpers")            -- 注意：UEHelpers 是 shared 库，必须 require
local TextLib = UH.GetKismetTextLibrary()

RegisterHook("/Script/UMG.TextBlock:SetText", function(self, in_text)
    local ft = in_text:get()               -- RemoteUnrealParam 只允许 get/set
    local s = ft:ToString()                -- 实测可用，能拿到完整原文
    local zh = lookup(s)                   -- 查自己的词条表
    if zh then in_text:set(FText(zh)) end  -- 改参数 => 本次调用即为中文
end)
```

**为什么是它**：

1. 在 UMG 函数**入口改参数**，因此**属性绑定每帧刷新也拦得住**（每帧都会再调一次 SetText，每次都被换成中文）。
2. **不闪烁**、零轮询开销、不需要 UI 对象缓存。
3. 实测 16000+ 次调用、98% 能取到非空原文、**零崩溃**。

**注意事项（都踩过）**：

- `RegisterHook` 要**尽早注册**并失败重试（UMG 模块可能尚未加载）；本包实现为启动后 3 秒开始、每秒重试至多 90 次。
- 回调参数是 `RemoteUnrealParam`，**只允许 `get()` / `set()`**；对其做任何反射调用（`GetClass` 之类）会触发 UE4SS 内部 `0xC0000005` 崩溃。
- `UEHelpers` 不做 `require` 时全局为 nil，直接调用报 `attempt to index a nil value`。

## 二、已证伪的路线（不要重试）

### 2.1 locres 覆盖 —— 本游戏无效

思路本身正确（社区对同款游戏亦有报告），但**对本游戏不成立**，证据链：

| 验证 | 结果 |
|---|---|
| 游戏是否有 locres | ✅ 有：`pakchunk0-Windows.pak` 内 `Content/Localization/Game/en/Game.locres`（1198 条） |
| 界面控件的 FText key 是否与 locres 一致 | ✅ 完全一致，例：控件 key `BAC7D49145997253F88BBAB1CE04F38C` ↔ locres 条目 `Music Volume` |
| 汉化后的 locres 是否成功打入并覆盖 | ✅ 已重打包进 `pakchunk0-Windows.pak` 本体（1715 条条目校验一致），同包字体生效可证 pak 被加载 |
| **界面是否变中文** | ❌ **完全没有**（设置菜单全英文） |

结论：这批 FText 在 cook 时已把英文原文固化，运行时**不做 locres 查表**（source-only）。

### 2.2 补丁容器 / 重建容器

- ❌ IoStore patch 容器、`_P.pak` → 被加载但不被采用
- ❌ retoc `to-zen` 重建 → zen chunk 与原生格式不兼容 → 崩溃
- ❌ retoc `pack-raw` 重建 → 不压缩 + 表格式不同

### 2.3 直接改 UI 蓝图容器

- ❌ 替换 uexp → 崩溃
- ❌ 等长替换 → 崩溃

**原因（实测判据）**：DataTable 资产在 chunk 内存在**唯一的 `SerialSize = uexp大小-4`** 字段，可精确更新；
而蓝图资产该字段**不存在**（对 5 个代表性蓝图做 4 种尺寸形态匹配，全部 0 命中），其长度信息散落在不可写的结构里。
`FString` 的 ASCII→UTF-16 编码切换还会进一步破坏结构，等长几乎不可能。

## 三、当前仍未覆盖的文本：Slate-only

**对象**：角色属性页标签（`Arcana`/`Presence`/`Crit Damage`…）、物品提示属性名（`Fire Resistance`）、物品名/品类（`SOBEK STATUETTE`/`Junk`）。

**排查证据**：

| 检查 | 结果 |
|---|---|
| 字面量所在资产 | `WB_Stats_Full`、`WB_ToolTipItemStatsSlot` 等蓝图（长度前缀 = 英文长度+1，确认为蓝图字面量） |
| hook 是否捕获 | ❌ 日志中这些文本出现 **0 次**（同会话里 `New Game`/`VIDEO` 等均被正常改写） |
| 轮询是否读到 | ❌ 未命中记录里没有它们 |
| UMG 属性是否可读 | ❌ 拆包/运行时读取这些控件的 FText 属性为**空** |
| 绑定函数枚举 | ✅ `WB_Stats_Full_C` 有 `Get Presence`/`Get Fire Resistance`… 等取值函数与 40+ TextBlock 属性 |

结论：文本只存在于 Slate 渲染层，UMG 侧既拿不到原文、也无从写入。
**唯一出路**是 UE4SS 的 C++ mod，hook `STextBlock::SetText(const FText&)`（Slate 是所有 UMG 文本的最终汇聚点）。

## 四、崩溃教训（重要）

1. **不要用 Lua 遍历常驻控件实例的 UObject 属性。**
   `obj:GetClass():ForEachProperty(...)` + `obj[属性名]` 读取，实测在 `WB_Stats_Full_C` 上**读取阶段**即触发 `0xC0000005`。
   （类级 `ForEachFunction` / `ForEachProperty` 仅用于**只读枚举类信息**是安全的，本包诊断即用此法。）
2. 历史崩溃点均在「对 hook 参数做反射」与「跨对象批量读写」两处；改参数（`in_text:set`）本身非常安全。

## 五、可复用的诊断手段

| 手段 | 用途 |
|---|---|
| `[MISS]` 收割 | hook 里对未命中原文去重打印到日志 → 用户正常游玩即可产出漏译清单 |
| `[CLASS]` 枚举 | `cls:ForEachFunction/ForEachProperty` 打印类结构 |
| `FindAllOf(类名)` | 取实例（注意本版 UE4SS 的 `FindAllOf("Class")` 返回 0，不能用） |
| 容器字节对比 | 用重打包前后条目清单 + 关键字段比对，判断「写了但没生效」还是「根本没加载」 |

## 六、环境备忘

- UE4SS 官方 release 最新即 `v3.0.1-1176-g1ba38db4`（2024-12），**不存在更新的官方版本**；
  社区流传的「较新构建」多在 CI 中，未经官方发布，来源需谨慎。
- 本游戏为 UE 5.5 Shipping，`.utoc/.ucas` 为 AES-256-ECB 加密、Oodle 压缩；密钥需自行从游戏获取（本仓库不提供）。
- `repak unpack` 在 mount point 为 `../../../` 时会因路径逃逸而失败，改用 `repak get` 逐条取出。

## 七、稳定性边界（最重要的运维结论）

| 通道 | 实测结论 |
|---|---|
| **UE4SS Lua pre-hook `/Script/UMG.TextBlock:SetText`（改参数）** | ✅ **稳定**：单会话 16000+ 次调用、零崩溃，属性绑定也拦得住、不闪烁 |
| **700ms/2s 轮询 + 对扫描到的对象批量 `SetText`** | ❌ **导致崩溃**（`EXCEPTION_ACCESS_VIOLATION`）：三次对照实验——关闭时长时间稳定；开启后“扫描命中并写入”后很快崩溃；去掉属性名探测后再开启，仍然崩溃 |
| **用 Lua 遍历实例属性**（`obj:GetClass():ForEachProperty` + `obj[属性名]` 读取，或往候选属性名写入） | ❌ **崩溃**（本项目中 3 次崩溃的同类根因） |

**因此本补丁自 v61 起只走 hook 通道**（`TICKS = 0`），这是"能不崩"的前提。若将来要恢复轮询以扩大覆盖，请先把上述对照实验重做一遍，不要直接打开。

**另注**：本项目未汉化时的崩溃（存档载入/长时游玩）在汉化前后都存在，属游戏自身问题，不要归因到补丁。
